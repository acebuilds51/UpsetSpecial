## Changes

### 1. The 5-minute final-score trigger no longer reads sheets or takes the lock when nothing is new (priority a)
- **What was wrong:** `checkGameFinalNotifications` runs every 5 min (288×/day) next to keepWarm. On every run it:
  - took the league-wide script lock, which pick saves wait on for up to 15s;
  - read the Season and Games tabs, just to find out that nothing was new.

  That costs trigger-runtime quota, and it contends with `submitPicks`, whose p95 is 12.6s.
- **What changed:**
  - It first checks the cached state, with no rebuild. If the cache shows no new finals and no pending wrap-up, it returns with zero sheet reads and no lock.
  - If there might be work, or there is no cache, it runs the full check exactly as before (lock, fresh sheet reads).
  - The logic is shared by one helper (`finalNotificationWork_`).
  - Push targets also come from the cached player list instead of the Players tab, which includes avatars.
- **Freshness:** every score fetch (keepWarm), Fetch Results, result override and manual edit (with `onSheetChange`) busts the state cache. So a cached "nothing new" is current. The one exception is a manual edit to `isFinal` without `onSheetChange` installed, which shows at most one cache lifetime (≤6 min) later.
- **Test:** new finals still get a full run with pushes and the wrap-up. A quiet run reads no Games/Season tab, takes no lock and sends nothing. Without a cache it falls back to the sheets and still never re-sends.

### 2. One Cloudflare stale signal per trigger run, sent after the rebuild (priority a)
- **What was wrong:** outside a web request, every cache bust sent its own `frontDoorStale` HTTP call, each with a `SpreadsheetApp.flush()`. A live-score keepWarm run sent 3 or more: the auto-default Picks write, the lock release and the state bust. That's ~0.3–1s of extra keepWarm time every 5 minutes during games. The signals also went out *before* the rebuild, so the Worker's next read often hit a cold Apps Script cache.
- **What changed:** new `runWithOneStaleSignal_(fn)` collects the busts and sends one signal when `fn` finishes. `keepWarm` and `checkGameFinalNotifications` are wrapped (the bodies are now `keepWarm_` / `checkGameFinalNotifications_`; the trigger handler names are unchanged). Web requests already worked this way.
- **Test:** a live-score keepWarm sends exactly 1 signal, and the state cache is warm when it goes out. An idle keepWarm sends 0. Web writes still send 1 each. The existing "triggers signal straight away" and "failing Worker" tests still pass.

### 3. Chat: no Players/Season reads on post, read or client-error report
- **What was wrong:**
  - `postMessage` (p50 8.8s) read the Players tab (every base64 avatar) twice: once for the poster, once for the push list. It also read the Season tab.
  - `getMessages` read the Season tab on **every** call, even when the messages came from its 30s cache.
  - `logClientError`, which arrives when the backend is already struggling, read the whole Players tab just to record a team name.
  - `sendPushToAllPlayers` (commissioner posts, reminders) read the Players tab too.
- **What changed:** new `playersLite_()` and `seasonYearLite_()` use the cached state (never rebuild), with the sheet as fallback. The same players, flags and tokens are used, so behavior is unchanged: the poster is excluded, `chatNotif: off` is respected, commissioner posts are admin-only and inactive players are rejected.
- **Expected impact:** a chat post does the append plus the FCM `fetchAll` and nothing else. Every `getMessages` cache hit is now sheet-free.
- **Test:** with the state cached, post, read and report do zero Players/Season reads. Pushes go only to opted-in, non-poster devices. Commissioner posts reach every device. The message is visible at once. Non-members and non-admin commissioner posts are still refused.

### 4. `getGameSummary`: ESPN summary cached per game
- **What was wrong:** every open of a game's detail refetched and parsed ESPN's large per-event summary (p50 5.1s, 6 of 6 slow). Several players watching the same game each paid for it.
- **What changed:** the parsed summary is cached per event: 60s while live, 6h once final. The AI recap still goes through its own existing cache. ESPN errors are never cached. The reply shape is identical.
- **Test:** 2 opens make 1 ESPN fetch with an identical reply. TTL is 60s for a live game and 21600s for a final one. A 503 is not cached.
