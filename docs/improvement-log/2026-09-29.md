## Changes

### 1. BUG: the Trophy Room double-counted this season's Upset Specials
- **What was wrong:** `getTrophyRoom` added up UpsetHistory rows, then separately counted the current season's Upset Specials from Picks. Since the v2 notifications code, the week wrap-up (`checkGameFinalNotifications` → `updateUpsetHistoryForWeek`) writes every finished week of **this** season into UpsetHistory. So every 2026 Upset Special was counted twice once its week wrapped up: attempts, hits and total upset points all inflated.
- **Fix:** the current-season count now skips any week that already has an UpsetHistory row for that player's team names. Weeks not yet wrapped up are still counted from picks, as before. The per-player cache key is bumped (`trophy_v3_` → `trophy_v4_`) so no inflated result is served after the deploy.
- **Behavior change:** each player's Trophy Room upset numbers for 2026 go down to the correct values. Nothing else in the payload changes.
- **Test:** before the wrap-up it shows 1/1/14; after the wrap-up still 1/1/14 (old code: 2/2/28). Older seasons add up correctly, the biggest hit wins, and other teams' rows are ignored.

### 2. Trophy Room speed (priority c, p50 ~6s)
- **What was wrong:** every uncached visit read the Players tab with every player's base64 avatar, the whole Picks tab, the 5.3k-row UpsetHistory, Games, Season and CareerHistory (for memberSince), plus 5 small tabs.
- **What changed:**
  - **Players, season, games and memberSince** come from the cached shared state (`getSharedState_()`, a helper that getState now uses too).
  - **Avatar:** only the visited player's is read, with a header + id-column + one-cell read (`readPlayerAvatar_`).
  - **Picks:** this player's Upset Specials come from the cached compact picks bundle, not the Picks tab.
  - **UpsetHistory:** summarised once per team name and cached (`getUpsetHistoryIndex_`, 6h when `onSheetChange` is installed, else 6 min). The week wrap-up busts it: `updateUpsetHistoryForWeek` now flushes and then calls `invalidateSheetCache('UpsetHistory')`. `onSheetChange` and `clearCareerCache()` bust it too.
  - The small tabs (NameClaims, SeasonTrophies, BowlWinners, PerfectWeeks, Bios) are still read directly.
- **Expected impact:** an uncached visit drops from ~6s to roughly the cost of 5 small-tab reads plus cache hits, likely 1.5–2.5s. Output is identical apart from the bug fix above.
- **Test:** a repeat visit reads none of Picks, UpsetHistory or Players, and the player's own avatar is still returned.

### 3. keepWarm: stop re-reading Picks every other run (priority a)
- **What was wrong:** the picks cache (`picksBundle_v1`) had a 10-min TTL and keepWarm runs every 5 min. So even with `onSheetChange` installed and nothing changing, keepWarm re-read the whole Picks tab (the largest sheet, 2.5k rows) about every other run, plus Ledger and BowlPicks. This is a likely reason keepWarm's p50 is still ~6.7s.
- **What changed:** when manual edits are watched (`sheetChangeTrigger` = 1), the picks cache lives 25 min, like the state cache. keepWarm's existing 15-min safety-net rebuild now refreshes the picks cache too. Unwatched behaviour is unchanged (10 min).
- **Freshness:** every write through the app or the helpers still busts it immediately, and so does every manual edit. The only thing that relied on the 10-min expiry was a raw script write that skips `invalidatePicksBundle_()` (CLAUDE.md already forbids that). Those now show within 15 min (hard cap 25 min).
- **Test:** TTL is 600 unwatched and 1500 watched. A raw write stays cached while fresh and appears after the 15-min rebuild.

### 4. Players no longer pay for live-score fetches during games
- **What was wrong:** both keepWarm (every 5 min) and every player's getState used the same 4-minute "last fetch" threshold. In the last minute before each keepWarm run, any app open did the whole ESPN fetch, auto-default picks, sheet writes and state rebuild inside the player's request. That's ~20% of game-time app loads, and a likely contributor to the getState p95 of 11.7s and the "timed out after 25s" phone failures.
- **What changed:** getState's fallback fetch now only runs if the last fetch was 7+ min ago, meaning keepWarm actually missed a run. keepWarm keeps 4 min, so it still fetches on every run. Scores still refresh every 5 min.
- **Test:** 4.5 min after a fetch, getState doesn't fetch but keepWarm does. At 8 min, getState fetches and returns the fresh scores.

### 5. Name-claim approval: batched CareerHistory writes
- **What was wrong:** `apiAdminReviewNameClaim` did 1–2 `setValue` calls per matching CareerHistory row (open item #3 from 2026-09-27).
- **What changed:** rows are updated in memory, then the `playerId` and `matched` columns are each written back with one `setValues`. The same rows get the same values.
- **Test:** zero per-cell writes, only matching rows change, and other columns are untouched.
