## Changes

### 1. Trophy Room: history tabs read once for everyone, not 5 tabs per visit (priority c)
- **What was wrong:** on every uncached visit (each player's result is cached for only 5 minutes), `apiGetTrophyRoom` read five sheets one by one: NameClaims, SeasonTrophies, BowlWinners, PerfectWeeks and Bios. It also called the PerfectWeeks read twice.
  - The 7-day p50 was 4.5s, and all 8 logged visits were slow.
- **What changed:** new `getTrophyTables_()` builds one compact summary of those tabs and caches it (chunked).
  - The cache is tied to the **state-cache generation**, so it rebuilds after any of these:
    - router writes: trophy archives, claim reviews, bowl winners, saveBio;
    - the week wrap-up (`archivePerfectWeeks_` calls `invalidateStateCache`);
    - manual edits (`onSheetChange`).
  - The expiry is only a safety net: 6h when manual edits are watched, 6 min otherwise. These are the same rules as the UpsetHistory index.
  - With this, a typical visit reads only the player's own avatar cell.
- **Expected impact:** an uncached Trophy Room visit should drop from about 4.5s to roughly the ~2s Google floor. The answers are identical.
- **Test:** the new test checks that:
  - trophies, champion years, bowl trophies, perfect weeks, the league perfect count and approved vs pending name claims all come out the same;
  - a second player's visit reads none of the five tabs;
  - saveBio, a manual edit and a perfect-week archive each show up at once.

### 2. Privacy fix: the Trophy Room no longer sends a player's bio email
- **What was wrong:** `getTrophyRoom` returned the whole Bios row, including the `email` column. Anyone can open anyone's Trophy Room, and the Worker caches the reply.
  - The app never shows this field (the bio form doesn't have it), and saveBio never receives it.
- **What changed:** bios go out without `email` and `_row`. The per-player cache key moved to `trophy_v5_` so no cached copy with emails is served after the deploy.
- **Behavior change:** none visible in the app.
- **Test:** covered in the change 1 test.

### 3. Chat reads answered from the Worker's copy, not Google (Worker us5 + backend)
- **What was wrong:** the Worker kept chat copies for only 30s ("as Apps Script's chat cache"). So 97 of 106 chat reads on 10/5 still went to Google.
  - One of those took 101s.
  - Each one that missed the 30s Apps Script cache also re-read the Messages tab.
- **What changed:**
  - **Worker:** `getMessages` copies now last until anything changes, up to 15 min. Posts and deletes pass through the Worker, which drops copies at once. Hand edits drop them through Apps Script's stale signal.
  - **Backend:** the chat cache now lives 10 min when `onSheetChange` is installed, and 30s otherwise (as before).
  - **Backend:** a new `invalidateChatCache_` is used by post, delete and now also `onSheetChange`, so a message deleted by hand in the Sheet disappears at once.
  - **Backend:** a generation check stops a read that started before a post from caching the list without the new message. With 30s this race was minor; with 10 min it matters.
- **Expected impact:** most chat polls are answered by Cloudflare in milliseconds, with fewer Google round trips and no Messages tab reads.
- **Tests:**
  - Backend:
    - the cache is 30s unwatched and 10 min watched;
    - posts, deletes and hand deletes are visible at once;
    - a read racing a post is not cached.
  - Worker: a copy is still current after 30s, a post drops it at once, it expires at 15 min, and each channel has its own copy.

### 4. Admin checks and the all-time leaderboard skip the avatar-heavy Players tab
- **What was wrong:** `requireAdmin`, which runs at the start of every admin action, read the full Players tab with every base64 avatar just to check `isAdmin`. That includes actions that never touch players, such as the email templates screen that timed out this week.
  - `getAllTimeLeaderboard` (p50 4.7s) did the same just to get team names.
- **What changed:** both now use `playersLite_()`. That is the cached player list, which has the same `isAdmin` / `active` / `teamName` fields, every write and manual edit busts it, and it falls back to the sheet when nothing is cached.
- **Expected impact:** about one fewer large sheet read on every admin action and every leaderboard rebuild.
- **Test:**
  - with the state cached, there are no Players reads and a non-admin is still refused;
  - demoting an admin by hand (with `onSheetChange`) takes effect at once;
  - with no cache, it falls back to the sheet;
  - the leaderboard output is unchanged.
